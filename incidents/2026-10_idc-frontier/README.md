## 3. 攻撃の流れ

2026-10-10時点で、侵入経路・攻撃手法・侵入開始時期は公表されていない。公式発表で分かっているのは、次の範囲にとどまる。

1. 第三者がIDCFクラウドの一部システムに不正アクセスし、ランサムウェア攻撃を行った。
2. 東日本リージョン1で障害が発生した（10月7日 3:40頃）。
3. 同社は東日本リージョン1をネットワークから遮断し、二次被害やデータ漏えいを防ぐためシステムを停止した。

## 4. 被害・影響

### 4.1 業務・事業

**公式発表（第2報）**：IDCFクラウドを契約する**495の企業・自治体**に影響し、対象の顧客には個別に連絡した。

**利用企業・自治体への波及（報道ベース）**：IDCFクラウドは、他社のサービスの土台としても使われていたため、直接の契約者でなくても影響を受けた。

- 契約者の公表：UDトーク、シックス・アパート、SKIMAなどが、自社サービスの停止の原因としてIDCFクラウドを名指しした。
- 事業者名を伏せたもの：茨城県・栃木県・小平市・多賀城市などの自治体のサイトや、ニッスイ日水物流の入出荷（17拠点）などが停止したと報じられている。
- バックアップ：シックス・アパートは別環境にバックアップを保管しており、他社クラウドへの移行を進めた。一方、UDトークのように「データの復元は難しい」と通知された事業者もあった。

**第3報での確認（公式）**：東日本リージョン1の4ゾーンでは、仮想サーバーの停止・再起動不可が起き、顧客データは「取り出しや復元が困難な見通し」とされた。復元は、**顧客自身が保持しているバックアップからのみ**可能となる。

### 4.2 個人情報

2026-10-10時点で、IDCフロンティア自身は**個人情報の漏えいの有無を調査中**（第4報に記載なし）。一方、利用企業の側では漏えいの可能性が公表され始めている（報道ベース）。

| 公表した企業 | 件数と項目 |
|---|---|
| JR東日本（えきねっと） | 約167万件（メールアドレス） |
| JR東日本（大人の休日倶楽部） | 約39万件（メールアドレス、会員番号、生年月日、クレジットカードの有効期限） |
| ビューカード（VIEW's NET） | 約403万件（メールアドレス） |
| 合計 | 最大約609万件 |

- 原因は、IDCFクラウド上にあったメール配信用の外部サービスに保存していた利用者情報が、第三者に閲覧・取得された恐れがあること。氏名・住所・電話番号・クレジットカード番号は含まれていないと説明されている。不正利用は確認されていない。
- 他の利用企業では、確認できなかったと公表したところ（グリニッジ、メディアリンクなど）と、調査中のところ（ニッスイ、小平市の住民情報など）が混在している。

## 6. 初動対応

- 東日本リージョン1をネットワークから遮断し、システムを停止した（完了）。二次被害やデータ漏えいの防止が目的。
- 侵入経路の特定と遮断を進めている。
- 東日本リージョン1以外のリージョンの安全性を確認している。確認が終わるまで管理コンソールを停止し、安全性が確認でき次第再開する予定。
- 影響を受ける495の顧客に個別に連絡した。
- 緊急対策本部を設置し（10月7日 9:00）、外部のセキュリティ専門企業と連携して調査している。
- 監督省庁と警察に報告・相談を進めている（第4報）。
- 顧客向けに、バックアップ手順の案内と移行環境の提案、仮想サーバーの起動・停止などの作業代行を行っている。
- 新たに公表すべき事実が判明した場合は速やかに知らせるとしている。

## 9. 分析: この事例から学ぶこと（暫定）

原因と再発防止策が未公表のため、現時点では被害の構造に限った分析にとどまる（本リポジトリ独自の考察。公式情報とは区別して読むこと）。

- **基盤の事業者が止まると、その上の事業者がまとめて止まる**：直接の契約者495社に加えて、契約者のサービスを使う企業、さらにその利用者へと影響が連鎖した。イセトー（委託先から約100団体）、KDDI（メール基盤から6社のISP）と同じ「共有基盤」型だが、**サービスそのものが丸ごと止まる**点で、名古屋港（港全体の共通システム）に近い。
- **「クラウドに置いた＝バックアップがある」とは限らない**：同じクラウド基盤の中にバックアップを置いていた事業者は、基盤と一緒に失った可能性がある。別の事業者の環境にデータを保管していた事業者は、早期に移行を進められた（報道ベース）。バックアップは「別の場所・別の事業者」に置く、という3-2-1ルールの意味が、実際の復旧の差として表れている。
- **自治体・インフラ系のサイトも例外ではない**：複数の自治体のサイトが影響を受けた。「どこのクラウドの上で動いているか」を、利用側が把握しているとは限らない。自社のサービスが依存している基盤（二次・三次の委託先）の棚卸しが、事業継続の前提になる。
- **利用者側が問われるのは「自社の責任範囲」**：基盤事業者の事故でも、利用者は顧客への説明と代替手段の用意を求められる。基盤が止まったときの代替（別環境への切り替え手順、問い合わせ窓口の案内、手作業での代替）を、平時から決めておく必要がある。
- **「止まる」だけでなく「漏れる」連鎖も起きる**：基盤の停止から2日後、利用企業のJR東日本・ビューカードが、基盤上のメール配信サービスに預けた最大約609万件の情報が閲覧・取得された恐れを公表した。顧客から見れば、直接契約していない事業者（メール配信の外部サービス）の、さらに先の基盤の事故である。委託先の確認は、二次・三次の委託先（再委託）まで及ぶ必要がある。
- **バックアップは顧客の責任範囲になった**：第3報は、復元は「顧客自身が保持しているバックアップからのみ」可能と案内した。クラウドの事業者がバックアップ機能を提供していても、それが同じ基盤の中にある限り、基盤の事故では頼れない場合がある。
- **情報が段階的に出る**：第1報は「不正アクセス」、約6時間後の第2報で「ランサムウェア」、翌日の第3報で「データ復元が困難」と、深刻さが段階的に明らかになった。利用者側の公表は、基盤側の公式発表に先行して出ている。
